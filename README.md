# Ритм

Планувальник дня: погодинний розклад, звички, фокус-таймер, вечірній підсумок і статистика.
React + Vite + TypeScript, дані зберігаються в `localStorage` браузера.

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # збірка в dist/
```

## Тести

```bash
npm test                  # юніт-тести (Vitest): підрахунки, дати, контраст квіткової теми
npm run test:e2e          # наскрізні тести (Playwright) у справжньому браузері + знімки екрана
npm run check             # усе разом: типи, юніт- і наскрізні тести
```

Перед першим запуском наскрізних тестів установіть браузер: `npx playwright install chromium`.

Знімки екрана (`tests/e2e/visual.spec.ts-snapshots/`) робляться й перевіряються в офіційному
Docker-образі Playwright у CI. На вашому комп'ютері шрифти згладжуються інакше, тому локально знімки
«падатимуть» — це нормально; щоб запустити лише функціональні тести:
`npx playwright test --grep-invert "знімки"`.
Якщо вигляд змінено навмисно, нові знімки робить workflow «Оновити знімки екрана». Запустити його можна:

- кнопкою: GitHub → Actions → «Оновити знімки екрана» → Run workflow → ваша гілка;
- або комітом у робочу гілку з міткою `[оновити знімки]` у повідомленні.

Workflow сам закомітить знімки в ту саму гілку. Перевірку, яку запускає коміт бота, GitHub ставить
на паузу («Approve and run» на сторінці PR) — підтвердьте її, або вона запуститься з вашим наступним комітом.

## CI і деплой

`.github/workflows/ci.yml` на кожен pull request перевіряє типи, запускає юніт- і наскрізні тести.
Після злиття в `main` той самий workflow публікує сайт на GitHub Pages:
https://thordiichuk.github.io/Ritm/

Одноразове налаштування: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

- Макети: `mockups/` (телефон — `phone-*.html`, комп'ютер — `desktop-*.html`)
- План, структура й модель даних: `docs/PLAN.md`
- Дизайн-токени: `src/styles/tokens.css`

Під 760px застосунок показує телефонні екрани з нижньою навігацією, ширше — комп'ютерні з рейкою.
Під час першого запуску створюються демо-дані; очистити їх можна в «Нотатки → Дані».

## Резервна копія

Дані живуть лише в браузері, тому час від часу робіть копію: **Нотатки → Дані → Зберегти копію**.
Завантажиться файл `ritm-backup-РРРР-ММ-ДД.json`. Щоб повернути дані (або перенести їх на інший
пристрій) — **Відновити з копії** й оберіть цей файл; перед заміною застосунок покаже, що всередині.
Формат і перевірка файлу — `src/data/backup.ts`.

## Головна сторінка і вхід

- Головна сторінка-представлення показується новому відвідувачу просто за адресою сайту (без маршруту в адресі): без власних даних і без входу. Щойно людина зайшла в застосунок, за адресою сайту відкривається вже «Сьогодні» (позначка `ritm:welcomed`). Пряме посилання на головну — `#/welcome`.
- `#/login` — вхід і реєстрація (`#/login?m=up` — одразу реєстрація). Після входу відкривається «Сьогодні».
- Картинки на головній — справжні знімки застосунку з демо-даними (`public/welcome/`). Якщо вигляд застосунку зміниться, їх варто перезняти.

## Акаунт і синхронізація

Без акаунта «Ритм» працює як раніше: усе лежить лише в браузері. Після входу (пошта + пароль) записи
синхронізуються між пристроями через [Supabase](https://supabase.com).

**Як це влаштовано**
- Дані завжди зберігаються в браузері, тож застосунок працює й без інтернету. Зміни відправляються, щойно з'являється зв'язок.
- Стан розкладено на окремі записи: кожен блок, задача, звичка, позначка звички за день, день і підсумок.
  Якщо той самий запис змінили на двох пристроях, перемагає пізніша зміна. Зміни різних записів не заважають одна одній.
- Під час першого входу на пристрої, де вже є власні дані, «Ритм» питає: об'єднати їх з акаунтом чи взяти дані з акаунта.
- Після виходу з акаунта дані з пристрою прибираються, а в акаунті лишаються.
- Код: `src/sync/` (`records.ts` — розкладання на записи, `engine.ts` — синхронізація, `account.ts` — вхід).

**Налаштування сервера (один раз)**
1. У Supabase: **SQL Editor → New query**, вставити весь файл [`supabase/schema.sql`](supabase/schema.sql) і натиснути **Run**.
   Файл створює таблицю `records`, правила доступу (кожен бачить лише свої рядки) і функцію запису.
2. **Authentication → URL Configuration**: Site URL — адреса сайту, у Redirect URLs — вона ж із `**` у кінці.
3. Адреса проєкту й публічний ключ записані в `src/sync/config.ts`. Секретний ключ (`service_role` / `secret`) у код не кладемо ніколи.

Наскрізні тести не ходять у справжній Supabase: адресу під час збірки для тестів підмінено, а відповідає
несправжній сервер із `tests/e2e/fake-supabase.ts`.

## Теми

- **Темна** (за замовчуванням) і **блакитна квіткова** — перемикач у «Нотатки → Налаштування → Тема».
- Усі кольори, шрифти, радіуси й тіні — CSS-змінні в `src/styles/tokens.css`: блок `:root, [data-theme='dark']` і блок `[data-theme='bloom']`.
- Вибір зберігається в `localStorage` (ключ `ritm:theme`) і застосовується скриптом в `index.html` ще до запуску React.
- Ботанічна графіка — `src/components/flora/Botanical.tsx`, рендериться лише в темі «bloom».
